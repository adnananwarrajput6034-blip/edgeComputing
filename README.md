# Federated Learning for Audio-Visual Sensor Fusion

Master's thesis (Berliner Hochschule für Technik). **Where should an edge
device train its model — on a server, partly on-device, or fully on-device?**
We compare three learning strategies for a system that learns to recognize
objects *by their sound*, so a robot can still perceive when the camera fails
(fog, darkness).

> **New to AI?** Start with [docs/PRIMER.md](docs/PRIMER.md) — a from-zero
> walkthrough (what AI/training/supervision mean → our strategy → simulation →
> results → the fusion extension).

## The core idea

A frozen, pre-trained **YOLOv8** looks at the camera and whatever it detects
("car") becomes the label for the *audio* recorded at that instant. This is
**cross-modal weak supervision**: vision (a solved problem) labels audio (the
thing we're training) for free, with no human annotation. The model actually
being trained is a small **audio CNN** that maps a sound's mel-spectrogram to
an object class.

Two models, never confused:
- **YOLOv8** — frozen labeler. Produces the training labels. Never trained, never ships.
- **AudioCNN** — the student. Learns sound → object. This is what the three strategies train.

## The three strategies (the thesis question)

Same model, same data — only **where training happens** changes:

| | Edge does | Ships to server | Server does |
|---|---|---|---|
| **A Centralized** | label only | raw audio + labels | STFT + training |
| **B Hybrid** | label + STFT | spectrograms + labels | training |
| **C Federated** | label + STFT + **train** | **model weights only** | FedAvg (average) |

## Headline results (measured, UrbanSound8K, 10 rounds, 2 nodes)

| Metric | A Centralized | B Hybrid | C Federated (tuned) |
|---|---|---|---|
| **Upload / node** | 65.9 MB | 48.7 MB | **3.99 MB** (16× less than A) |
| Test accuracy | 0.71–0.73 | 0.70–0.73 | 0.70–0.74 |
| Edge compute | 0 | 9.6 s STFT | 158 s training |
| Server compute | trains (heavy) | trains | averages only (0.5 s/round) |
| Data leaving device | raw audio | spectrograms | only weights |

**Takeaway:** moving training toward the edge (A→B→C) collapses bandwidth and
server load and improves privacy; the cost is edge compute. Federated *matches*
centralized accuracy — but only once the local learning rate is tuned down
(naïve FedAvg destabilizes even under IID data). Full analysis in
[docs/RESULTS.md](docs/RESULTS.md).

## Two tracks

- **Science track** — laptop, UrbanSound8K replayed over a real MQTT broker.
  Produces the measured comparison (needs identical data + ground-truth labels).
- **Hardware track** — real Raspberry Pi 5 with USB webcam, live capture +
  YOLO labeling. Validates the pipeline on real edge hardware; supplies the demo.

Same code, different sensor front-end. How the code executes end to end —
what you launch, per-strategy flow, sim vs real Pi — is in
[docs/CODE_FLOW.md](docs/CODE_FLOW.md).

## Quickstart

```bash
# 1. environment (Python 3.13)
python3 -m venv .venv
.venv/bin/pip install -e ".[edge,server,dev]"

# 2. dataset + preprocessing cache
.venv/bin/python scripts/download_urbansound8k.py
.venv/bin/python scripts/prepare_urbansound8k.py

# 3. train the baseline AudioCNN (~90 min, or skip to run cold)
.venv/bin/python scripts/train_audio_cnn.py

# 4. start the MQTT broker (separate terminal)
/opt/homebrew/sbin/mosquitto -c configs/mosquitto.conf

# 5. run a strategy comparison (a | b | c)
.venv/bin/python scripts/run_strategy.py --strategy c --num-rounds 10 --local-lr 5e-5
```

Outputs land in `results/strategy_{a,b,c}/run_*/`. Full command reference:
[docs/EXPERIMENTS.md](docs/EXPERIMENTS.md).

```

                    run_strategy.py      orchestrate an A/B/C comparison

                    prepare/download_urbansound8k.py   dataset setup
                    test_*.py            pipeline verification

  common/           config, constants, utils
  edge/             Pi-side: sensors, processing (stft/vision),

  server/           laptop-side: aggregation (fedavg), training, models (audio_cnn)

```

Naming: **`src/experiments/` = code**, **`results/` = run outputs** — distinct.
